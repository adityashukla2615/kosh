The problem

People can see their balance.
They can't see their future.

  • Banking and investing apps show what you have, not whether it's enough.
  • "What if I lose my job?" or "can we afford the car?" needs a spreadsheet most people never build.
  • Advice is either expensive, or free and quietly selling a product.
  • Generic AI chatbots will happily invent a number.
"We earn well. I just don't know if we're doing okay."

- the sentence every one of our test households opened with

Innovation 1 · Recommendations that are tested, not templated

Every suggestion is simulated before it's shown

  1. 11 generators spot situations: costly debt, thin cushion, idle cash, unplanned surplus, protection gaps, FD-heavy long-term money…
  2. Each candidate is applied to a copy of the plan.
  3. The whole plan is re-run - goals, health, cash flow.
  4. Ranked by priority-weighted change in goal odds + safety + urgency.

Innovation 2 · An agent that can't make numbers up

Claude plans and explains. The engine does the maths.

  • 7 tools: snapshot, run_scenario, check_goal, next_best_actions, analyze_spending, search_guides, get_assumptions.
  • Multi-step tool loop; every step shown to the user.
  • Grounding check: every ₹ and % in the answer must match a tool result. Untraced → sent back to the model once to fix.
  • Refusal or outage → offline planner answers with the same tools.

Explainability

Assumptions are a page, not a footnote

Visible

Inflation 6%, education 9%, equity 11.5% ± 18%, surplus leakage 50%… each with a one-line reason.

Editable

Change any value and every probability, chart and recommendation re-runs.

Honest odds

We plan for ~80% odds, not the average (which is a coin flip). Goals keep their real asset mix - FDs stay FDs.

Categories, never products. Not a SEBI-registered adviser, and says so once - not on every line.

OpsCloudWatch, X-Ray, error alarm
IaCAWS SAM
CI/CDGitHub Actions → OIDC → sam deploy → s3 sync → smoke test
Why a Function URL, not API Gateway?

Agent turns with several tool calls can exceed API Gateway's 30 s limit.

Why BM25, not a vector DB?

15 hand-written notes. Right tool for the size; Knowledge Bases is a one-function swap.

Same code everywhere

Laptop, Docker, this demo and Lambda run the identical Express app. The live demo is one container; the table is the production target, linted in CI.
